## Why we are building this

We want every couplet of Ferdowsi's Shahnameh to have a place you can step
inside. Persian miniature painting, Nastaliq poetry and a generative score
turn the book into a journey through light, landscape and story. The ambition
is the complete Shahnameh, made carefully enough that the art
serves the words.

<div dir="rtl">

شاهنامه میراثی برای خواندن و دوباره زیستن است. می‌خواهیم راهی بسازیم تا هر بیت،
با نگارگری و موسیقی، دری به جهان فردوسی باز کند؛ برای فارسی‌زبانان امروز و
نسل‌هایی که هنوز این داستان‌ها را نشنیده‌اند.

</div>

The reader is Persian and right-to-left. Scroll slowly into the paintings, or
move between couplets with the arrow keys and on-screen controls. Your last
reading position stays in your browser. Sound is synthesized locally, and the
site respects reduced-motion preferences. No account is needed.

![A couplet in Nastaliq over an illuminated miniature, with reading controls](docs/media/reader.jpg)

## Inside the paintings

Original generated illustrations follow a Timurid–Safavid miniature direction:
mineral blues, shell gold, stacked landscapes and a luminous centre that opens
into the next scene. Prompts and character sheets live beside the source so
contributors can keep the story visually coherent.

## Run locally

Use Node.js **24.22 or newer in the 24 LTS line** and pnpm **12.16.1**, pinned in `package.json`.

```sh
git clone https://github.com/farzinnasiri/visual-shahnameh.git
cd visual-shahnameh
make install
pnpm dev
```

Open `http://localhost:5173`. Optimized AVIF paintings are included, so a
fresh clone can read the completed chapters immediately. To generate or check
new sections, run `pnpm setup`, install Chromium with
`pnpm exec playwright-core install chromium`, and install `ffmpeg`.

```sh
pnpm status             # completed sections, claims and the next section
pnpm check 02.01        # text, paintings, screenshots and the full score
pnpm build              # typecheck and production build
```

## Contribute

Fork the repository, create a branch, and open a pull request to `main`.

> **Codex is required to contribute chapters.** Install the Codex app and sign
> in with your own account for image generation. If you do not have Codex,
> do not use the chapter-building prompt below.

Use this prompt with your coding agent, whether Codex, Claude or Grok.
Codex handles image generation. Replace **X** with the number of chapters
you want to add.

```text
Build the next X chapters of Visual Shahnameh.
Follow AGENTS.md and docs/BUILDER_BRIEF.md.
Follow the README's shared-claim workflow before starting any sections.
Use Codex for image generation, then complete the section checks and reports.
```

See the [contributor guide](CONTRIBUTING.md) for setup and submitting your PR.
UI, accessibility and engine fixes are welcome too.

### Reserve work before starting

[GitHub Issues](https://github.com/farzinnasiri/visual-shahnameh/issues) is the
shared reservation list across contributors and forks. Agents must follow
these steps before generating paintings:

1. Update from the upstream `main` branch and check open claim issues. Choose
   a small, contiguous range of unfinished sections with no active claim.
   Use the section ids from `text/chapters`. The number before the dot is the
   chapter: `09.01` is the first section of chapter 09.
2. Open an issue titled `[Claim] 09.01–09.05`, replacing the example with your
   range. List the exact section IDs in the body. The issue author owns the
   claim; assignment or maintainer approval is not required.
3. Recheck open claims before starting. The earliest open issue takes priority
   if ranges overlap. Close your conflicting claim and choose another range.
4. Link the finished PR to the claim with `Closes #<issue-number>`. Keep the
   issue open while working, post progress if work takes longer, and close it
   to release the range if you stop. A merged PR closes the linked claim.

Large chapters can be split between several non-overlapping claims. Check
claims in the upstream repository, not just your fork. `pnpm status` and
`scripts/next_sections.mjs` currently read local files and local claims only;
they do **not** fetch GitHub reservations. Agents must check Issues separately.
The `work/claims/` locks still coordinate agents sharing one checkout.

## Deployment and security

[shahnameh.world](https://shahnameh.world) runs entirely on Cloudflare Workers
Static Assets and its CDN. GitHub Actions checks pull requests without
production credentials. An owner push or merge to `main` checks and builds the
site, then deploys that exact build in a separate job. `develop`, if used,
runs checks only. See [DEPLOY.md](DEPLOY.md) for the token and environment setup.

Only maintainers may update `main` or `develop`. Production credentials
belong only in the restricted `production` environment,
never in source, prompts, reports or browser-facing `VITE_` variables.

See [SECURITY.md](SECURITY.md) for reporting a vulnerability.
